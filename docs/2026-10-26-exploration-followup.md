# 候选耗尽与重复空转：二次复查

本轮只做本地代码复查、离线回归和通用 iOS 编译，没有安装、启动或运行真机，也没有提高恢复次数来延长测试。

## 新发现并修复的遗漏

| 问题 | 后果 | 修复与离线证据 |
| --- | --- | --- |
| 横向方向只进入过滤器，XML仍是ScrollView | C++按纵向类只生成上下动作；上下被过滤后直接假耗尽 | 横向区域映射为引擎已支持的HorizontalScrollView，方向同时进入动作生成、过滤和执行校验；真实C++跨层测试验证左右各两次无变化后正确耗尽 |
| 状态栏也被标记为inputVisible，屏幕外输入宿主也算可见 | 键盘开关可能共用上下文封禁记录 | 只识别键盘/输入助手，要求其实际边框与屏幕有正面积交集；状态栏、屏幕外键盘、空输入宿主不标记可见，输入内容仍不保存 |
| 无变化次数跨成功跳转累计 | 偶发无变化→成功→偶发无变化也会永久封禁 | 同一上下文动作成功改变树时清除该动作无变化累计；测试证明两次不连续失败不封禁，连续两次仍封禁 |
| 旧NOP只绑定树指纹 | 量化后指纹相同但候选位置/方向变化，仍沿用旧耗尽状态 | 耗尽上下文由树指纹、排序去重后的候选操作集合、返回能力共同组成；新集合使NOP缓存与稳定计时失效。重排相同候选不造成虚假变化 |
| 裁剪后的纵向列表很矮，被判断为横向 | 对纵向控件发左右手势，进一步耗尽 | 滚动轴判断使用原始尺寸，非屏幕裁剪尺寸；保留可见边框用于操作 |
| 同尺寸推测容器抢先占用点击区域，原生按钮被去重掉 | 普通容器不命中时，真正按钮也不可选 | 同尺寸、启用的原生操作后代优先于推测容器，仍只保留一个点击候选 |
| 遍历深度超过60时仅截断分支，但整棵树被接受 | 缺失关键出口后误判候选耗尽 | 深度超限使本次采集预算失效，整个残缺树走snapshot_rejected，不参与守卫观察、候选耗尽或新发现统计 |

上述问题均有离线失败用例，修复后通过。跨层测试此前实际复现“横向候选被策略层耗尽”，说明只看适配层和守卫各自通过是不够的。

## 再次复查：数字语义、残留动作与重叠控件

本次仍未运行真机，新增并修复三类已复现问题：

1. **原生数字按钮的语义被归一化吞掉。** 同一标识、同一位置的按钮从1001变成1002，原来被当成同一上下文，继承旧封禁。现在保留Button/Cell/Link/Switch的数值标签；明确的HH:MM（可带秒）计时文本仍去抖。被推测为可点击的普通文字仍有启发式语义限制，不声称控件树等于业务状态。
2. **路径重开把已经消失的旧动作当出口。** 原接口只查历史blocked表。现在beginNextPassForCandidates:canGoBack:必须显式传入本轮真实候选，只允许当前动作集合里的有效历史跳转重开，移除无候选参数的旧接口。新增“旧位置可重开、当前位置和BACK都已封禁”的用例，正确拒绝虚假重开。
3. **同位置不同身份的前景控件被背景控件去重覆盖。** 相同身份、相同几何的重复节点仍合并；不同身份保留，CLICK返回待实时解析的目标组。只在全部查询完成且唯一目标可操作时执行；两个目标都可操作、查询超时/快照失败、实时匹配数不一致均拒绝猜测。整组共享查询检查期限，不为每个候选重复分配完整预算。执行和日志使用实际选中目标的元数据，防止错误使用另一候选的editable/secure属性。

验证覆盖唯一前景命中、双重命中、部分查询未完成、数字按钮更新后重新选择，以及相同物理区域共享封禁预算；串联真实C++动作生成、原生候选适配和守卫测试通过。Python80项回归通过。新修复尚未在真实App上复验，不宣称已经消除所有动态页面空转。

## 第三轮复查：实时身份查询与候选计数对齐

重点复核上一轮的数字标签、当前动作集合重开约束及重叠候选解析。确认一处遗漏并已修复：liveKey按type、identifier、label和frame计数，但实时查询在identifier非空时只匹配identifier。同类型、同位置且共用identifier的两个不同标签控件会在每次查询中都被计入，实际matches=2、候选liveMatchCount=1，前景唯一可点击时也会被拒绝；重复拒绝后可能封禁该区域。

现在将实际使用的查询条件抽为Foundation可验证的livePredicateForTarget：普通控件同时核对identifier与label（空identifier也精确匹配），type仍由XCTest descendantsMatchingType约束，geometry仍由实时快照校验。密码框的label在候选计数中被脱敏，因此查询只核对identifier，避免用空脱敏标签匹配真实密码框标签；匿名密码框仍受类型、几何、匹配数量和查询预算约束。没有增加随机点击或放宽多目标歧义检查。

新增回归先在旧查询语义下失败（shared identifier with another label must not inflate live match count），修复后通过，同时验证带标识及匿名密码框。控件树、探索守卫、真实C++策略串联及引擎测试通过，Python 26+39+15项通过，Runner通用iOS目标build-for-testing通过（/private/tmp/fastbot-review3-build-20261026.log）。未运行真机，未提交、未推送。本轮未确认数字标签或重开约束有其他新的回归；离线结果仍不证明动态真实页面完全无空转。

## 第四轮复查：相邻区域与恢复后的耗尽确认

本轮只做离线检查，确认并修复两处遗漏：

1. **有效候选被邻近区域干扰，可能提前耗尽。** XML输出、C++动作和守卫封禁都使用取整后的整数区域，但targetForAction原先按各坐标差≤1匹配。例如两个按钮x=10.1和11.1，引擎返回x=11时两个候选都落入容差，随后被判歧义；只剩x=10.1候选时，x=11动作还可能错误绑定到它。现统一按与XML相同的%.0f取整结果精确比较。相同整数区域仍保留重叠候选实时唯一命中校验。
2. **恢复后继承旧耗尽确认，过早消耗恢复次数。** Runner在重启前调用clearPending，但此前只清待观察动作。如果重启后的树和候选集合没变化，confirmExhaustion沿用已经满足的次数和起始时间，第一次快照就再次耗尽。现在clearPending同时清耗尽观察窗口，保留动作封禁与发现历史，每次恢复重新满足至少三次检查且跨越两秒。没有清空无效动作封禁，没有扩大两次恢复上限。

两处新增用例分别先失败，修复后通过。新增真实C++引擎串联用例覆盖两个相邻区域都可正确绑定，各执行两次无变化后输出no_available_action，守卫也报告无可用动作且不会重开永久无效路径。恢复用例覆盖相同树重启后重新等待完整窗口，同时旧封禁仍在。既有水平滚动、有界A/B循环、候选变化和重叠目标回归通过。真机行为仍未复验，离线回归不等于所有动态页面已无空转。

本轮最终验证：控件树、守卫、真实C++策略串联和独立引擎回归通过；Python 26+39+15项全部通过；Runner通用iOS目标build-for-testing通过，日志/private/tmp/fastbot-review4-build-20261026.log；git diff --check通过。未跑真机，未提交或推送。

## 真机后修复：连续拒绝不能替代候选耗尽

依据20261026-151520-bef387真机原始记录：最后15次拒绝属于同一控件树指纹的13个不同动作，仍有55个快照候选；结束原因为consecutive_rejections，未进入耗尽恢复。普通文字和滚动区域的实时查找均可能被拒绝；旧日志只有粗略target_stale_or_not_hittable，无法倒推各自失败的具体原因。

修复后由守卫统一维护stalledRejectionCount：一个尚未封禁动作消耗有限重试或首次被封禁，属于候选筛除进展，不增加停滞计数；已经封禁的动作被重复选中，或NOP等无法规范化的动作被重复返回，才累计停滞，连续15次仍停止。单操作在同一上下文的临时查找失败最多两次，原有耗尽稳定窗口、有效路径重开约束、最多两次恢复及总时长不变。成功执行和恢复均清零停滞计数，快照失败仍单独按连续10次处理，正常快照会重置其计数。没有按候选总数无限放大一个全局阈值。

实时查找新增targetResolution诊断：整组/单次查询超时、查询数量超限、快照失败、没有匹配节点、匹配数不一致、匹配但不可点击，以及不同身份目标同时可点击。每个查询记录检查数量、几何匹配数量、预期数量及候选路径，不序列化XCUIElement对象。动作日志同时记录停滞计数及已封禁动作数。查询结束后也检查期限；XCTest原生调用无法抢占，这不是严格硬超时保证。

报告增加实时控件校验中文统计，分为整次解析原因和各查询原因，仅统计未执行的动作，明确一次操作可能有多条查询记录。旧日志缺少诊断时返回未知（null），不会为历史真机结果补造失败原因。

- 新增诊断回归先失败、修复后通过，覆盖超时、歧义、不可点击及JSON序列化。
